## Unreleased

- Fix the auto-learning ambiguity check for devices that already have own area profiles: a competitor area is now compared through the shared room profile unless the device's own profile there covers at least two scanners, so profiles emptied by "Reset Training" or covering only one scanner no longer let a wrong area confirm itself. Reference trackers keep the previous behaviour. A room profile without overlapping scanner pairs (the neutral score 0.5) no longer counts as a competitor.
- For button-trained devices, areas where the device has no mature own profile are scored from the shared room profile with a factor of 0.55 (`UKF_ROOM_ONLY_ANCHORED_FACTOR`) while one of the device's button-trained areas matches the current readings with at least 0.3 (`UKF_ROOM_ONLY_ANCHOR_GATE`); when none matches, the device is most likely elsewhere and these areas keep their full weight. Room scores without supporting data are ignored. The best device score of the button-trained areas is reported as `ukf_anchor_score` in the area diagnostics of `bermuda.dump_devices`. A perfect room match still passes the switching threshold, a neutral 0.5 does not. Devices without button training are unchanged. A device whose own profiles are all empty is no longer routed to the fingerprint path because of them; without mature shared room profiles it takes the min-distance path.
- Add the service `bermuda.reset_room_auto_learning` (`area_id`, one or more areas). It removes the auto-learned data from the shared room profiles of these areas and keeps button training; it changes nothing before the learning data is loaded. "Reset Training" of a device now logs a hint to this service, because it leaves the shared room profiles untouched.
- Fix unloading the integration (for example "Reload") deleting all shared room profiles: the room profiles are now saved on unload.
- The services `bermuda.dump_devices` and `bermuda.reset_room_auto_learning` are now registered once when the integration is set up (Home Assistant `action-setup` rule). While no entry is loaded, a call fails with a validation error instead of an unknown action.
- Add translations of both services for every language (French and Norwegian had none).
- Run codespell in pre-commit, as `AGENTS.md` requires, and fix the typos it found.
- The release drafter keeps the fork version scheme: drafts are named after the last release with the next fork prerelease number (for example `v0.8.7-FMDN-RC1.2` after `v0.8.7-FMDN-RC1.1`) instead of the plain upstream version (`v0.8.7`). Drafts are created as prereleases that are not marked "Latest"; clear the prerelease flag when publishing, otherwise HACS shows the update only to users with beta versions enabled, and set "Latest" if the release should become the latest GitHub release.
- Fix `bermuda.dump_devices` with `redact: true` (and the integration diagnostics, which use it) leaking MAC addresses held in dataclass or tuple values, such as the scanner addresses in a device's `area_tests`. Dataclasses are now redacted field by field and tuples like lists.
- The area switch diagnostic of a virtual (scannerless room) win now reports the `VIRTUAL` path, the scannerless flag, the virtual distance and the target area instead of a min-distance decision.
- **Breaking:** The area switch diagnostic sensor (disabled by default) no longer changes on every coordinator cycle. Its state keeps the decision path, the reason with every number replaced by `#`, the areas, the UKF mode, the profile kind (`Prof:BTN` or `Prof:AUTO`), the offline scanner count and failed sanity checks; it drops the UKF score, distances, profile sample count, coverage penalty and advert age. Its attributes drop `ukf_score`, `ukf_current_score`, `ukf_threshold`, `profile_samples`, `virtual_distance_m`, `distance_incumbent_m`, `distance_challenger_m`, `distance_diff_percent`, `nearest_scanner_m`, `nearest_scanner_area`, `winner_advert_age_s`, `top_candidates` and `coverage_penalty`, and `reason` has its numbers replaced by `#`. Before, an enabled sensor fired a `state_changed` event and wrote a recorder row about every second per device although its attributes are not recorded. The full values remain available via `bermuda.dump_devices` (`diag_area_switch`, `area_tests`). The min-distance and virtual-distance paths now also store their `area_tests`, so the sensor shows their decisions too.
- **Breaking:** Bermuda now requires Home Assistant 2026.6.0 or newer, which runs on Python 3.14.2 or newer.
- The device tracker is now a Home Assistant scanner entity (`BaseScannerEntity`). It reports `in_zones` (for example `zone.home` and any zone enclosing it) and honours an associated zone set in the entity settings; if that zone is deleted, the tracker state becomes unknown and Home Assistant raises a repair issue until the setting is changed or the zone is recreated. The recorder now skips only the `scanner` and `area` attributes instead of all attributes.
- Fix nearly every Bermuda entity being removed from the entity registry (and recreated seconds later) on each start or reload. The orphan cleanup ran right after the first refresh, which returns early while the Bluetooth ID data loads, so the device list was empty or partial; base-address extraction misread real unique_ids (iBeacon addresses contain underscores, scanner entities use the WiFi MAC, `_training_floor` was cut as `_floor`); and the duplicate check grouped a device's per-scanner sensors, and the global sensors, as duplicates of each other. The cleanup now runs 5 minutes after setup, skips itself while the device list is not populated, matches unique_ids against known addresses by prefix, and compares entity types including the scanner part. Listeners of the `remove` events (for example Proximity's `tracked_entity_removed` repair) are no longer triggered for entities of devices Bermuda currently knows; entities of unknown addresses and stale duplicates are still removed. Among duplicates, the entity under the device's current unique_id is kept first, then one under any known address.
- Speed up the startup orphan cleanup: unique_id prefixes are resolved through an index built once per run instead of scanning all devices for each entity.
- **Breaking:** Area, floor and distance sensors no longer expose `last_good_area_age_s`, `last_good_distance_age_s` and `area_retention_seconds_remaining`, and the scanner online binary sensor no longer exposes `last_seen_age_seconds`. These values changed on every coordinator cycle and forced a `state_changed` event plus a recorder row per entity per second, even though they were excluded from recording. The flags `area_is_stale`, `area_retained` and `area_source` remain. The underlying monotonic timestamps (`area_state_stamp`, `area_distance_stamp`, `last_seen`) remain available via `bermuda.dump_devices` and the integration diagnostics (subject to the dump size limit).
- Compute the active scanner count once per update cycle instead of once per stale device.
- Add configurable FMDN modes and EID parsing, improving manual selection and avoiding duplicate devices through canonical address normalization.
- Harden FMDN EID candidate extraction and deduplicate shared tracker identities to prevent ghost devices and capture variable-length EIDs.
- Align MAC normalization with Home Assistant formatting, separate pseudo-identifier handling, and stabilize FMDN metadevice keys to avoid address collisions.
